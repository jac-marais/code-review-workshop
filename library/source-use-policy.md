# Source Use Policy

## Authority

- Use official Git and GitHub documentation for command and API behavior.
- Use standards and official security guidance for security practice coverage.
- Use primary empirical studies for claims about reviewer behavior or AI review performance.
- Use first-party engineering guides as practitioner evidence from that organization, not universal law.
- Treat vendor material as evidence of the vendor's method or product behavior only.
- Treat the owner-authored review protocols as workflow requirements and prior practice.

## Provenance

- Give every consequential external source a stable ID.
- Store the canonical URL, publication date or version, retrieval date, and exact section or page locator.
- Distinguish what a source states from what the workshop infers.
- Preserve disconfirming evidence and authority limits.

## Local Review Protocols

`SRC-001` is a derived local protocol and `SRC-002` is owner-authored. Use the local skills under `.agents/skills/` and see [`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md) for attributed material. Do not depend on an external copy.

## Copyright

Store short quotations only when exact wording matters. Prefer paraphrase with a locator. Do not store full third-party papers, books, or paywalled articles unless their license permits redistribution.

## Repository Data

Treat reviewed repositories, pull request discussions, logs, test data, credentials, and generated artifacts as scoped private data. Do not place their content in the workshop library unless an eval fixture was made for that purpose.

## Recency

Search current sources for platform APIs, model capabilities, active benchmarks, package behavior, and security guidance that may have changed. Record the research cutoff for landscape claims.
