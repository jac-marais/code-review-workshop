# Open Research Threads

## THR-001: Real Pull Request Precision

- Question: Does the method keep useful recall without producing review noise on ordinary, unseeded pull requests?
- Why open: synthetic fixtures have known ground truth, while real reviews do not.
- Next evidence: blinded review of real TypeScript, Go, and Python pull requests, followed by maintainer disposition of every proposed comment.
- Promotion effect: blocks claims of broad production validation, but does not block the first TypeScript workbench trial.

## THR-002: Language Portability

- Question: Which parts of the generic method fail when applied to Go and Python?
- Why open: the first evaluation slice covers TypeScript only.
- Next evidence: one public regression behavioral case in each language, chosen for a language-specific failure mode but scored with the same output contract.
- Promotion effect: the workshop may claim a language-neutral method, not proven equal quality across languages.

## THR-003: Workbench Unique Yield

- Question: Do all five mandatory workbenches add enough distinct verified evidence to justify their cost?
- Why open: source evidence supports distinct scenario methods, not this exact five-workbench set.
- Next evidence: record unique verified yield and false-positive burden across fresh trials and real reviews.
- Promotion effect: keep the baseline during early trials. Merge or narrow a workbench only after repeated zero unique yield.

## THR-004: Retrieval Calibration

- Question: Which expansion triggers capture cross-file defects without diluting attention?
- Why open: both insufficient context and flat large context have documented failure modes.
- Next evidence: preserve retrieval receipts for misses, false positives, and successful causal traces.
- Promotion effect: progressive retrieval is accepted, while exact stopping thresholds remain experimental.

## THR-005: Existing Comment Semantics Outside GitHub

- Question: How should deduplication map to platforms without GitHub review threads and line-side anchors?
- Why open: current operational evidence is GitHub-specific.
- Next evidence: adapter contracts for another review platform.
- Promotion effect: blocks a platform-neutral publication claim, not harness-neutral review instructions.

## THR-006: Missing Coverage Research Lane

- Question: Would a separate standards-led coverage study change the five baseline workbenches or scorecard?
- Why open: the assigned coverage lane stalled and returned no usable report after one retry.
- Current mitigation: local security and robustness protocols, NIST SSDF, OWASP guidance, the review-science lane, and the method-falsification lane supplied overlapping coverage.
- Next evidence: rerun this lane only if trials reveal a missing failure class or the workbench map needs redesign.
- Promotion effect: does not block convergence because the completed lanes already challenge the consequential method claims.
